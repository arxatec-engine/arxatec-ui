## SVG transparente de Apple — 2026-10-09

> **Branch:** `main` · **PR:** #20 cerrado por petición del usuario · **Published:** pendiente

**Intent.** Compartir el icono de Apple con la plataforma y eliminar el fondo
negro incrustado en la imagen usada por el selector de acceso.

**What changed.** `AppleIsotype` conserva el path del logo como un SVG inline
transparente, con un viewBox cuadrado ajustado, `fill=currentColor` y props SVG.
Se exporta desde el barrel público de iconos y se muestra en `Marcas`,
`AppleEnTemas` y la guía de estilos. README y guía operativa documentan el
contrato. La versión preparada es `0.1.70`; la plataforma consume el icono
mediante un parche limitado de pnpm sobre su `arxatec-ui@0.1.68` instalado.

**How it was verified.** Pasan `pnpm exec tsc -b tsconfig.build.json`, ESLint de
los archivos modificados, `npm run build:lib`, `npm run build-storybook`,
Prettier del alcance y `git diff --check`. Se revisan las exportaciones JS/TS y
el SVG sin rectángulo de fondo. La plataforma pasa tipos, lint y builds web y
Electron con el parche y conserva los pins y peers del lockfile.

**Publication steps.** Paso 1: se creó la branch propia y el borrador de PR #20;
el usuario pidió después cerrar el PR y llevar el cambio directamente a `main`.
Se integra el icono en `main` siguiendo esa instrucción explícita. Pasos 2 y 3:
publicación desde main limpio y actualización de consumidores pendientes del
owner y de la antigüedad de siete días. El parche permite el uso actual del
icono en la plataforma sin una nueva versión de registro.

**What is still open.** Publicación del paquete. Al consumir una release
que incluya el icono, se retira el parche temporal de la plataforma.

## Logo de Arxatec Academy y Arxatec Management — 2026-10-09

> **Branch:** `feat/logo-variants` · **PR:** pendiente de apertura · **Published:** pendiente (`0.1.71` preparada)

**Intent.** Elegir el logo del producto desde el mismo componente compartido,
usando los dos SVG entregados por el usuario.

**What changed.** `Logo` acepta `variant="arxatec" | "academy" | "management"`;
omitirla conserva el logo original. Los SVG de Academy y Management conservan
sus trazos, separadores y viewBoxes, y usan `currentColor` para tomar el color de
`className`. Se exportan `LogoProps` y `LogoVariant`, se agregan un selector y
las stories `Academy`, `Management` y `EnTemas`, y README documenta el contrato.
La versión preparada sube de `0.1.70` a `0.1.71`. La guía operativa y las
incidencias consultadas se actualizan con la versión de registro re-verificada
(`0.1.68`) y los resultados actuales de lint.

**How it was verified.** Pasan `pnpm exec tsc -b tsconfig.build.json`, el chequeo
de tipos de la story de Logo, ESLint de `src/components/logo`,
`npm run build:lib`, `npm run build-storybook`, `npm pack` y `git diff --check`.
Los datos SVG coinciden exactamente con los archivos entregados y el path de
Arxatec original. Se inspeccionan `Default`, `Academy`, `Management` y `EnTemas`
en Chromium, con ambos temas y selección por args. Un consumidor aislado del
tarball pasa tipos, build Vite y revisión visual: el logo predeterminado coincide
con `variant="arxatec"`, se conservan las proporciones y el color responde a
`className`. No hay errores de ejecución en el navegador. `npm run lint`
mantiene los 12 errores y una advertencia previos, documentados en
[`../known_issues/2026_W32.md`](../known_issues/2026_W32.md).

**Publication steps.** Paso 1: branch propia y PR para revisión del owner.
Pasos 2 y 3: publicación desde `main` limpio y actualización de consumidores
pendientes. Se valida el tarball en un consumidor temporal; el registro sigue
en `0.1.68` y no se cambian consumidores de producción.

**What is still open.** Merge del owner, publicación de `0.1.71` y actualización
de consumidores respetando su política de antigüedad de siete días.
