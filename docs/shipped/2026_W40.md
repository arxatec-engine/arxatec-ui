## File viewers and panels load when opened — 2026-10-04

> **Branch:** `feat/lazy-file-view` · **PR:** pending owner review

**Intent.** Keep document engines, HEIC conversion and unvisited panels out of
platform startup while preserving existing consumers and editing state.

**What changed.** Version `0.1.69` adds `file-view/core`, independent engines and
`file-view/lazy`. `lazyPanels` defaults to false; opted-in sheets retain visited
panels until close or file change. A lightweight local-worker configuration
survives deferred PDF setup; engine and worker versions must match. PDF and image
loading callbacks reach the sheet. HEIC conversion imports only for HEIC files.
Licensed local font subsets keep existing families and weights and load on
request. React Hook Form and Tiptap core/React become compatible peers to share
the host's contexts and types. Legacy exports remain available.

**How it was verified.** Frozen pnpm install, source declarations, library build,
Storybook build and ESLint of all changed source files passed. The real story
verified lazy mounting, inactive queries, retained panels and reset on file
change/close. An isolated platform consumes the packed `0.1.69` tarball; browser
requests verify JPEG without HEIC/PDF, PDF without Office/Excel/templates, a local
hashed worker and editor loading on visit. Its web, PWA and Electron delivery
checks use real assets. Full UI lint retains the same 12 errors and one warning
on the base and candidate; see [D-1](../known_issues/2026_W32.md).

**What is still open.** Owner review/merge, publication from clean `main`, then
seven days of registry age before updating the platform. The local tarball is
validation only; it must not become the production dependency. Live deployment
and seven days of real performance samples remain separate acceptance work.
