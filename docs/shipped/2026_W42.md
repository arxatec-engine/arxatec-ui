> **Branch:** `main` (explicit owner request) · **PR:** not opened · **Source version:** `0.1.72` · **Published:** pending

audit so Arxatec products share editing behavior, save feedback and integration
icons.

**What changed.**

- Moved 17 components from the platform: property rows, inline text/options/date/
  Markdown/duration controls, table date/options controls, autosave indicators,
  selector table headers, hexadecimal color pickers and four provider SVGs.
- Added public `/editable-fields` and `/provider-icons` entries, declarations and
  main-entry reexports. Preserved existing primitives and icons.
- Added `EditableFieldsProvider` for translated copy, date-fns locales, date
  formats and swatches, plus `InlineFieldTrigger` for application-specific
  selectors. Persistence, routing and services remain with the consumer.
- Namespaced SVG definitions per icon instance. Moved existing component unit
  tests and excluded tests, setup and stories from the published package.
- Added Spanish, English and table-cell stories. Updated the README with source
  paths, API examples and local integration instructions.

**How it was verified.**

- ESLint passed for the migration's source, public entries, configuration and
  unit-test files; the final story adjustment also passed ESLint.
- `npm run build:lib` passed, including declarations, stylesheet and fonts.
- `npm pack --dry-run --json` listed every declared package export and no test,
  setup or story files. The candidate package is `0.1.72`.
- Inspected `Patterns/EditableFields` → `Spanish`, `English` and `TableCells` in
  Chrome: property layout, translated date/save copy, color trigger, table cells
  and all four provider icons rendered correctly.
- An intermediate unit-test run passed 12 files / 98 cases. The suite was not
  repeated after the final saved-status/context adjustments.
- Local platform integration was refreshed with
  `pnpm update arxatec-ui --ignore-scripts`. Existing dependency versions and the
  consumer's React/Tiptap/form peer versions were preserved.
- The final consumer passed `pnpm typecheck`, ESLint for its affected source and
  `pnpm build` against the local package.

## Shared file/folder visuals and explorer surfaces

> **Branch:** `main` (explicit owner request) · **PR:** not opened · **Source version:** `0.1.72`, extending the unpublished candidate

**Intent.** Prioritize reusable file and folder presentation found by following
the Lawyer Platform documents layout into its document module.

**What changed.**

- Added `FileTypeIcon` (the former `IconType`), MIME family styles and extension
  labels; added `FolderIcon` with default/shared/drive marks and SVG props.
- Moved ten explorer surfaces plus action dropdown/context menus. Public
  component props, action/column/item types and the grid constant are exported
  from the main package. Document models, services and router imports were
  replaced with generic types, props and callbacks.
- Added URL-based `FileThumbnail` with loading, fallback, forwarded container
  ref and image failure state scoped to its source. It does not import PDF or
  office engines. Local/workspace/cloud adapters remain in the consumer.
- Added an accessible action-trigger label and keyboard-operable breadcrumb
  buttons. Card keyboard activation ignores events from nested controls.
- Moved three existing unit-test files and adapted their imports/mocks. Added
  stories for file families, folder variants, grid/table views and thumbnail
  states. The README lists the public APIs and actual source paths.

**How it was verified.**

- Library TypeScript, ESLint and `npm run build:lib` passed.
- `npm pack --dry-run --json` includes the new implementations and declarations
  and excludes all test/story files.
- Inspected the five stories in Chrome, including unavailable/broken-image
  thumbnail fallback and folder marks in the dark theme, without page errors.
  No unit-test suite was run for this migration.
- Refreshed the consumer's local package without changing unrelated dependency
  pins. Its TypeScript, ESLint and production build passed with the new
  main-package exports.

**Publication steps.** This extends the existing unpublished `0.1.72` candidate.
The registry still reports `0.1.71` on 2026-10-12. No commit, push or npm publish
was run; the consumer uses `file:../../arxatec-ui` until the release workflow and
registry update are completed.
