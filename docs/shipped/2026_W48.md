# Shipped — 2026 week 48

## Editable XLSX workbook

> **Branch:** `feat/editable-excel` · **PR:** none · **Candidate:** `1.1.0` · **Published:** pending

**Intent.** Open an existing workbook and edit its supported sheets, ranges and
basic formatting through the current grid, with a compact set of controls.

**What changed.** `FileXlsxDocumentEditor` is available through `/file-view/xlsx`.
It keeps an immutable input session and a revisioned draft across visible
sheets, and exports a full workbook snapshot in a deferred worker. Typed cell
values, formula expressions, TSV paste, basic font/color/number/alignment/border
formatting, dimensions and safe merges are supported. Export preserves hidden
sheets and unrelated values/styles. Formula caches are invalidated for data
edits and marked for recalculation. Unknown workbook parts reject editing.
The preview defaults and XLS basic read-only behavior remain compatible.

**How it was verified.** Library TypeScript, focused XLSX ESLint, library build
and Storybook build passed. The full component suite passed 368 tests;
the utility run passed all 86 tests, including styled-empty-cell limits, ISO
date consistency, bounded actual ZIP expansion and unsupported inline XML.
The date/style isolation test was repeated after the final style-cloning change.
Storybook was inspected in Chrome
at desktop/mobile widths and dark theme, including real-worker save/reopen
across two sheets. Four real-engine Platform Playwright cases passed at 1280/390 px,
including replacement/reopen, conflict and lost-response retry. The release validation uses a tarball in an isolated
Platform checkout. Full lint retains the 12 errors and two warnings documented
in [D-1](../known_issues/2026_W32.md); no XLSX lint errors were introduced.

**Publication steps.** Source version bumped; local library build and `npm pack`
ran. npm still reports `1.0.0`. Git delivery is directly on `main`; no npm
publication or registry consumer update ran. Platform's real manifest and lockfile still use `1.0.0`; its local
tarball dependency is confined to the isolated validation copy.

**What is still open.** Merge the reviewed branch and publish from clean `main`, then update Platform from
the registry. Formula calculation, binary XLS writing, sheet management and
advanced workbook features remain future work, as described in README.

## Preserve connected workbooks when editing cells

> **Branch:** `feat/editable-excel` · **PR:** none · **Candidate:** `1.1.0` · **Published:** pending

**Intent.** Let basic cell editing open existing workbooks with imported data
without deleting their connection or query metadata on save.

**What changed.** Connections, query tables and their worksheet relationships
are retained with their original compressed bytes. Save remaps worksheet links
to the generated parts, preserves known workbook location/chart-reference
metadata and updates the calculation flag. The editor never refreshes external
sources. Other unsupported features, protection and resource limits remain
guarded. No dependency or public API was added.

**How it was verified.** The component suite passed 374 tests in 44 files,
including six metadata regressions, ZIP CRC checks and worksheet renumbering.
Library TypeScript, focused XLSX lint and the library build passed. A read-only
local reproduction opened, edited, saved and reopened a 9,000-cell workbook;
its connection/query parts remained identical and Service accepted the output.
The isolated tarball consumer passed typecheck and all five Chrome Playwright
cases, including connected-workbook save/reopen. No account file was replaced.

**Publication steps.** The library was built and packed locally; the new tarball
was installed only in the isolated Platform consumer. Unrelated resolved
packages were unchanged. The owner validated the local editor before authorizing
Git delivery on `feat/editable-excel`. npm publication and the real registry dependency update
remain pending.

**What is still open.** Registry delivery follows the original release order.
Editing or refreshing data connections and broader workbook features remain
outside this basic editor.

**npm handoff.** Release version is `1.1.0`, a compatible minor addition over
registry `1.0.0`. Git push does not stage an npm release. For maintainer approval,
after merge, run `npm run build:lib` and `npm stage publish` from clean `main`; a maintainer then reviews and approves
the staged version with 2FA. Once npm serves `1.1.0`, update the real Platform
consumer from the registry and validate it before its Excel delivery.
