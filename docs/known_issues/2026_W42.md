# Known issues — 2026 week 42

## Remaining dependency advisories, including the development shadcn CLI

> **Live** · **Detected:** 2026-10-16 · **Last verified:** 2026-10-17 against
> base `main` `d9cbd05` and `fix/security-viewer-dependencies` (`0.1.75` candidate).
> npm registry latest: `arxatec-ui@0.1.74`.

The runtime graph no longer contains the reported `braces`, `ajv` or
`@cyntler/react-doc-viewer` advisories. The CLI is retained as a development
dependency to preserve the local workflow, so `braces` remains in the full audit.
The registry also reports other existing dependency issues. No automated PR
audit gate exists.

Reproduction: `pnpm install --frozen-lockfile`, then `pnpm audit --json` and
`pnpm audit --prod --json`.

- Full pnpm audit: 104 findings on current main, 100 afterward (6 low, 45 moderate,
  45 high, 4 critical). These are advisory findings across versions, not 100
  independent vulnerabilities.
- Production pnpm audit: 81 findings on current main, 15 afterward (1 low,
  3 moderate, 11 high, 0 critical). Affected packages: `xlsx`, `@tiptap/core`, `prosemirror-view`,
  `vite`, `esbuild`, `postcss`, `nanoid` and `source-map-js`.
  These are the library's pinned development/install context, not the consumer
  tree: the isolated Admin consumer with its existing SheetJS override has zero
  production advisories with the candidate tarball.
- The historical npm lock's full audit has 53 affected package entries;
  `npm audit --omit=dev` has 18 and none of the three reported targets.
  This lock does not represent the current manifest; see D-2 in `2026_W32.md`.

The isolated Admin consumer reproduces 10 npm production / 12 full affected
package entries with published `0.1.74`; with the `0.1.75` tarball, synchronized
locks and the same other package versions, these fall to 0 / 2. The two remaining
entries are development-only `@tailwindcss/typography@0.5.20` and its
`postcss-selector-parser@6.0.10` dependency
([advisory](https://github.com/advisories/GHSA-rj75-hqrm-r3gf)). The library's
development Typography `0.5.19` uses the same vulnerable parser. Updating the
consumer and its Typography parser remains separate from publishing the library;
no audit exclusions or overrides were added by this fix.

Examples requiring a separate dependency update and behavior validation:

- Development-only `shadcn@4.3.0` retains `braces@3.0.3` through `fast-glob` and
  `ts-morph`: [stack exhaustion](https://github.com/advisories/GHSA-vfj7-8cjw-p6xm).
  npm still has no patched `braces` release. Moving the CLI to development
  dependencies removes it from the published runtime graph; this does not patch
  the CLI itself, and the full audit continues to report the advisory.
- `xlsx@0.18.5`: [prototype pollution](https://github.com/advisories/GHSA-4r6h-8v6p-xvw6)
  and [ReDoS](https://github.com/advisories/GHSA-5pgg-2g8v-p4x9).
- `@tiptap/core@3.22.4`: [attribute merging](https://github.com/advisories/GHSA-cp6q-959q-f8rh)
  and [Markdown ReDoS](https://github.com/advisories/GHSA-j95f-988m-3j2f).
- Development-only Vitest browser tooling `4.1.4`: three critical findings,
  including [browser command authorization](https://github.com/advisories/GHSA-p63j-vcc4-9vmv).

The fix retains all remaining pnpm package versions. Updating the editor,
spreadsheet engine and development tools needs its own compatibility work;
this delivery does not establish a clean full audit. Follow-up is in `BACKLOG.md`.
