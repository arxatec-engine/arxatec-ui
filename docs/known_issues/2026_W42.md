`pnpm audit --json` and `pnpm audit --prod --json`. The pnpm graph is authoritative;
the historical npm lock still has the install problem recorded in D-2 of

These are advisory findings across dependency versions, not counts of independent
vulnerabilities or an audit of an application's resolved tree. Remaining production
findings affect `@tiptap/core`, `prosemirror-view`, `vite`, `esbuild`, `postcss`,
`nanoid` and `source-map-js`. The full graph additionally reports Storybook/Vitest,
CLI and other development tooling. Updating those requires compatibility work;
this Excel delivery does not establish a clean full audit.

The earlier `xlsx@0.18.5` finding is resolved in this candidate: XLS compatibility
uses the official SheetJS `0.20.3` tarball. Both current audits report no
`xlsx`, `exceljs` or `ssf` advisory. The three spreadsheet parsers are development
dependencies bundled into the deferred worker, so the full audit is necessary
when reviewing their code; a production-only graph would omit them. Publishing
the kit and updating a consumer are separate steps, and were not performed here.

The October audit totals and isolated Admin comparison described the `0.1.75`
candidate and are historical evidence, rather than the current library graph.
Existing consumers must be checked at their actual published library version.
